# Documentation — Background Record-Keeping

## Problem type

A session needs a running record of research, findings, decisions, and solutions as it develops, so nothing has to be reconstructed later — this runs continuously in the background rather than being invoked as a one-off request.

## Diagnostic questions

- What research, findings, decisions, or solutions have occurred in the session so far?
- When the user asks for a recap, exactly what did they ask for — the latest research, a specific topic, or a specific statistic?

## Methodology

1. After each substantive exchange, note what was found, decided, or solved.
2. Keep the record in the background — don't surface it unprompted.
3. When asked for a recap, pair the requested item with its corresponding solution or decision, rather than restating the entire history.

## Connects to (v1)

No v1 template — this is a background capability that supports whichever v1 or v2 deliverable is currently in progress by keeping its context traceable.

## Deliverable

An always-current internal record; a targeted recap, paired with its solution, when specifically requested.

## Requirements

- Never lose track of earlier decisions
- Never dump the entire history when only one item was actually asked for
