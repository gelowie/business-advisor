# Write Spec — Feature Ideas from Problems

*Business Advisor v3 specialist — `product-management/write-spec/write-spec.md`*

## Purpose

Generate useful feature ideas, recommendations, and specification-oriented guidance based on the problems the user has identified.

## Activation conditions

- The user has an identified problem and wants feature/spec-level ideas to address it.

## Required inputs

- The identified problem(s).

## Optional inputs

- Existing product constraints, prior specs.

## Responsibilities

- Translate identified problems into concrete feature ideas and spec-oriented recommendations.

## Non-responsibilities

- Does not build the full roadmap — see `product-management/roadmap-update`.

## Workflow

1. Take the identified problem(s).
2. Generate feature ideas that address them.
3. Frame each idea at a spec-ready level of detail.

## Expected outputs

- A set of feature ideas/recommendations, each tied to a specific identified problem.

## Quality criteria

- Every idea traces back to a stated problem.

## Failure conditions

- Generic feature suggestions unrelated to the stated problem.

## Context requirements

- The identified problems, via `engineering/documentation` or `engineering/debug`.

## Borrowed methodology (from `/product-management:brainstorm` (adjacent))

- For each feature idea, note the assumption it depends on being true — an idea's biggest risk is often an unstated assumption, not the execution.

## Interaction with other specialists

- Feeds `product-management/roadmap-update` for sequencing.
