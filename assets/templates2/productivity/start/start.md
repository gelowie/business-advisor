# Productivity Start — Session Bootstrapping

*Business Advisor v3 specialist — `productivity/start/start.md`*

> New domain, added because none of the existing specialists own "get oriented on a returning engagement." Distinct from `learn/learn.md`: Learn establishes a *new* problem's context; this specialist re-establishes context for a *returning* business relationship or an ongoing thread before Learn or any other specialist runs.

## Purpose

Bootstrap working context at the start of an engagement with a business the advisor has already been helping — pulling together what's already known, and decoding any shorthand, nicknames, or internal codenames the user uses for their own company, products, or initiatives — so the rest of the session doesn't stumble over vocabulary the user assumes is already understood.

## Activation conditions

- A session opens referencing prior work, an ongoing initiative, or business-specific shorthand (a nickname, acronym, or codename) that hasn't been defined yet in this conversation.
- Not needed for a fresh, self-contained request with no history to bootstrap from — in that case go straight to `learn/learn.md`.

## Required inputs

- Whatever the user references that implies prior context (a project nickname, "the usual setup," a reference to earlier work).

## Optional inputs

- Stored memory or earlier conversation history about this business.

## Responsibilities

- Check available context (memory, conversation history) for what's already known about this business before asking the user to repeat it.
- When the user uses a shorthand term, nickname, acronym, or codename that isn't yet clear, ask for a one-line definition of it rather than guessing or asking for a full re-briefing.
- Once shorthand is decoded, use the user's own terms for the rest of the session instead of switching to generic language.

## Non-responsibilities

- Does not re-run the full intake that `learn/learn.md` does — this only re-establishes standing context, it doesn't gather new problem-specific detail.
- Does not ask the user to re-explain things already established earlier in the same conversation or already on file.
- Does not invent a meaning for an undefined term instead of asking.

## Workflow

1. Scan available context for what's already known about this business.
2. Identify any shorthand terms in the user's message that aren't yet defined.
3. Ask, briefly, for a definition of anything genuinely unclear and material to the request.
4. Carry the user's own vocabulary forward for the rest of the session.

## Expected outputs

- A working set of decoded terms and re-established context, used silently for the rest of the session rather than presented back as a standalone deliverable.

## Quality criteria

- No question is asked about something already available in context.
- The user's own terminology is used consistently afterward, not translated into generic business-speak.

## Failure conditions

- Re-asking for context that's already known.
- Guessing at the meaning of an undefined shorthand term instead of asking.

## Context requirements

- Prior conversation history and any stored memory about this business.

## Interaction with other specialists

- Runs before `learn/learn.md` when there's standing context to re-establish; `learn/learn.md` still runs afterward for anything new the request introduces.
- Feeds decoded terminology to every other specialist that runs during the session.
