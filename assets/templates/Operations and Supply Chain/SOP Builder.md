# SOP Builder

## Summary

Turns a process description into a clear, numbered standard operating procedure that a first-time reader could follow unaided.

## Inputs

- **Process name** — [what this covers]
- **Who performs it** — [a role, not a specific person's name]
- **Current process** — [the real steps as they happen today, including any workarounds]
- **Tools or systems involved** — [software, equipment, forms]
- **Definition of done** — [the end state that confirms the process is complete]

## Deliverable

1. Purpose — one sentence on why this process exists
2. Trigger — when this process should be used
3. Numbered steps, written specifically enough for someone who's never done this before
4. Tools or access needed before starting
5. Definition of done, stated explicitly
6. Common mistakes or edge cases, and how to handle them

## Requirements

- Steps must be numbered and specific ("open X, then click Y"), not general ("process the request")
- Write for a first-time reader with no prior context
- Use the actual tool and system names provided rather than generic placeholders
- Separately flag any step in the current process that looks inefficient or risky
